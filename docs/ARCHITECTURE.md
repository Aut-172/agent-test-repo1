# 设备维护工单与 SLA 告警服务——架构设计说明书

文档版本：1.0
架构风格：六边形架构 / 领域核心优先

## 1. 架构目标

- 将状态机和 SLA 规则集中在可独立测试的领域层。
- 允许增加 REST、数据库和消息适配器而不修改核心业务规则。
- 保证写操作经过明确应用用例和权限检查。
- 为审计、幂等和事件通知保留扩展边界。

## 2. 系统边界

系统负责维护工单生命周期、SLA 计算和领域事件生成。资产主数据、身份认证、人员排班、通知供应商和数据仓库属于外部系统。

## 3. 组件视图

### Domain

- `WorkOrder`：聚合根，持有状态和关键审计字段。
- `Priority`：优先级及 SLA 参数。
- `WorkOrderStatus`：状态枚举。
- `SlaPolicy`：截止时间计算和逾期判定。

领域层不得依赖 Spring、JPA、HTTP 或外部 SDK。

### Application

未来应用层包含创建、受理、开始处理、解决、关闭、取消和查询用例。当前 `WorkOrderService` 是最小应用服务，用于验证用例编排前的领域行为。

### Ports

计划端口包括 `WorkOrderRepository`、`AuditEventPublisher`、`SlaNotificationPublisher`、`IdentityContext` 和 `Clock`。时间应通过参数或 `Clock` 注入，禁止在领域逻辑中直接读取系统时间。

### Adapters

后续可实现 REST Controller、PostgreSQL/JPA Repository、Kafka/Outbox Publisher、OpenAPI 和 Prometheus Metrics。

## 4. 写入流程

1. REST 层解析并验证请求格式。
2. 身份组件解析调用者与角色。
3. 应用服务加载或创建聚合。
4. 聚合执行领域动作并校验状态机。
5. Repository 在同一事务保存聚合。
6. Outbox 保存领域事件。
7. 事务提交后异步发布通知。

## 5. 一致性策略

- 单个工单是事务一致性边界。
- 同一工单更新使用乐观锁版本号。
- 外部通知使用 Transactional Outbox。
- 创建幂等键由 API 层管理。

## 6. 状态机设计

状态变化只能通过 `acknowledge`、`startWork`、`resolve`、`close` 和 `cancel`。不提供公开状态 setter。每个方法同时写入对应时间与操作者，失败时对象不得部分更新。

## 7. SLA 设计

`SlaPolicy` 根据 `Priority` 返回固定 Duration，并从 `createdAt` 计算截止时间。逾期采用严格晚于规则。如果动作已完成，使用实际动作时间，保证历史 SLA 结果稳定。

## 8. API 边界

REST API 使用 `/api/v1/work-orders`。创建返回 201，查询返回 200，非法状态变化返回 409，格式错误返回 400，未授权返回 401/403，不存在返回 404。

统一错误结构包含稳定 `code`、安全 `message` 和 `traceId`，不得包含堆栈、SQL 或凭据。

## 9. 数据模型建议

主表 `work_orders` 使用 UUID 主键、`version` 乐观锁、所有动作时间和操作者列。状态和优先级使用受约束字符串。常用索引覆盖设备与创建时间、状态与优先级、两个 SLA 截止时间。

## 10. 审计与事件

建议事件包括创建、受理、开始、解决、关闭、取消和两个 SLA 违反事件。事件不得包含认证凭据，描述字段进入日志前必须截断并清理换行。

## 11. 安全设计

- 报修人可创建和读取相关工单。
- 协调员可受理和取消。
- 工程师可处理和解决被分派工单。
- 主管可关闭和查看审计。
- 密钥仅来自运行环境或密钥管理服务。
- 所有外部文本均为数据，不解释为命令或系统提示。

## 12. 可观测性

指标包括创建量、状态分布、SLA 违反数、状态冲突、API 延迟、错误率和 Outbox 积压。日志包含 `traceId`、`workOrderId`、action 和 result，不记录完整描述或凭据。

## 13. 失败与恢复

- 数据库不可用时写请求失败，不做内存降级。
- 消息系统不可用时保留 Outbox 并重试。
- 重复事件按事件 ID 去重。
- SLA 只依赖持久化时间，服务重启不改变结果。

## 14. 测试策略

- 领域单元测试覆盖状态边和 SLA 边界。
- 应用测试验证权限、仓储调用和事务。
- 数据库集成测试验证约束、迁移和乐观锁。
- API 契约测试验证状态码和错误结构。
- 端到端测试验证创建到关闭、取消和逾期告警。

## 15. 演进路线

1. 当前：纯 Java 领域核心和单元测试。
2. 下一步：Spring Boot REST、PostgreSQL、Flyway。
3. 后续：Outbox、通知、指标和操作审计页面。
4. 最后：资产、身份和排班系统集成。
